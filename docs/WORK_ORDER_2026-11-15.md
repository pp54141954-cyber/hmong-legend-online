# Hmong Legend MMORPG V2.0 — คำสั่งงานหลักและตรวจฐานเกม (15 พฤศจิกายน 2026)

> ขอบเขต: **Hmong Legend MMORPG V2.0 (Pixel Art MMORPG)** ไม่ใช่กระดาน Hmong Legend 2D Anime ซึ่งเป็นอีกงานหนึ่ง

## 1. อำนาจและหลักการพัฒนา (เจ้าของอนุมัติ)
- ผู้ช่วยรับบท **ผู้พัฒนาหลัก** ตรวจไฟล์ วางแผน ออกแบบ เขียนโค้ด เชื่อมระบบ ทดสอบ และส่งมอบ; เจ้าของโครงการเป็นผู้ตรวจรับ
- อนุญาตปรับโค้ด ระบบ ภาพสไปรต์ ใบหน้า ผม ชุด แอนิเมชัน การเดิน/โจมตี/สกิล/เอฟเฟกต์/แผนที่/วัตถุ/NPC และเพิ่มทรัพยากรที่จำเป็น **โดยไม่ต้องขออนุญาตซ้ำทุกขั้นตอน** ตราบใดที่รักษาธีมม้งและความต่อเนื่องของตัวละครจนจำได้ว่าเป็นตัวเดิม
- ก่อนแก้: **สำรองหรือแยก branch** รักษาไฟล์ต้นฉบับ บันทึกสิ่งที่เปลี่ยน จำกัดขอบเขตรอบงาน ตรวจจริงก่อนรายงาน PASS
- ไม่สรุปว่าภาพตัวอย่างคือฟีเจอร์ที่เชื่อมเกมแล้ว; ไม่สรุปว่าการทดสอบจำลองคือการทดสอบบนมือถือจริง
- ทรัพยากรภายนอกทุกชิ้นต้องบันทึกผู้สร้าง URL ใบอนุญาต เงื่อนไข และเครดิตที่จำเป็น คำว่า “ฟรี” ไม่ใช่หลักฐานสิทธิ์
- ตรวจสอบกลไกในเกมที่มีอยู่ก่อนเพิ่มเติม ห้ามส่งหน้า HTML ที่อ้างไฟล์ภาพ/สคริปต์ที่ไม่มีในชุดส่งมอบ

## 2. ข้อกำหนดเกมที่ยืนยันเป็นเป้าหมาย
- Pixel Art สไตล์และสเกลเดียวกัน เดินสลับขาจริง **4 ทิศ**, เท้าไม่ไถล, idle, anticipation, impact, recovery, เอฟเฟกต์ออกจากจุดอาวุธที่ถูกต้อง
- เลเวลตัวละครสูงสุด **100**; **8 อาชีพ** × **3 สาย**, **15 สกิลต่ออาชีพ**, ช่องใช้สกิล **6 ช่อง**; **Job EXP** สูงสุดระดับ **50**; สกิลทั้งหมดปลดล็อกได้ที่ Job ระดับ **30**; แต้มสกิลสูงสุด **50 แต้ม** (รายละเอียดใช้จ่ายแต้มต้องเช็กข้อกำหนดและโค้ดอีกครั้ง)
- NPC, ร้านค้า, ซื้อขาย, กระเป๋า, อุปกรณ์, สถานะ, อาวุธ, เงิน, รางวัล ต้องเชื่อมกัน; ค่าที่ไม่ยืนยันระบุเป็น **ทดลอง**
- **Server authority:** client ส่งคำสั่งกระทำ ไม่ส่งดาเมจ/รางวัลที่เชื่อถือได้; เซิร์ฟเวอร์ตรวจระยะ คูลดาวน์ HP การตาย เงิน ของรางวัล และบันทึกข้อมูล
- เป้าหมายโหลด **20–50 คนต่อโซน**; ต้องตรวจบนโฮสต์จริงก่อนประกาศรองรับ

## 8. ระเบียบสถานะและหลักฐาน
- **ออกแบบแล้ว**: มีข้อกำหนด/ภาพร่าง แต่ยังไม่มีฟีเจอร์เชื่อมระบบจริง
- **พัฒนาแล้ว**: มีโค้ดในฐานที่เลือก แต่ยังไม่ผ่านเกณฑ์ทดสอบที่ประกาศ
- **รอทดสอบ**: ทดสอบที่จำเป็นยังไม่รันหรือยังไม่มีหลักฐาน
- **ทดสอบผ่าน**: มีการรันจริง ระบุ commit, คำสั่ง/อุปกรณ์, PASS และหลักฐาน
- **พบปัญหา**: มีอาการ/การจำลอง/หลักฐาน บันทึกใน `docs/BUGS.md`
- **ข้อมูลยังตรวจสอบไม่ได้**: ต้องระบุชัดเจน ห้ามเปลี่ยนเป็น PASS เพราะคาดเดา

เอกสารนี้เป็น **บันทึกตรวจฐานและคำสั่งงาน** ไม่ได้ยืนยันว่าแก้บั๊ก/เพิ่มฟีเจอร์ในรอบนี้เสร็จแล้ว และไม่ได้แก้ภาพหรือเซิร์ฟเวอร์จริง
